# Requests from N1 (session engine)

The engine calls these through `lab/session/sources.py`, which falls back to a built-in
stub when a module is missing or raises, so nothing here blocks a merge. Shapes below
are what the adapter reads; extra fields are fine.

## N3: `lab/tasks/bank.py`

- `pick(skill, tier, seen) -> bank_id` (`skill` is a trap id, `seen` a list of bank ids).
- `load(bank_id) -> dict` (or an object with the same attributes):
  - `public`: the task in the exact shape of `contract/mock_task/task.json` (any `id`; the
    engine replaces it with the slot id `t1`/`t2`/`t3`).
  - `dir` (or `public_dir`): folder with `tables.json` and the CSVs (what
    `lab.workspace_sql` reads).
  - `key`: `{trap, verdict, careful: {verdict, trap, note}, careless: {verdict, trap,
    note}, columns: [column names that matter], hints: [three hint lines, gentlest
    first, never naming the trap], checks: [check ids]}`. `columns` decides which
    learner queries count as useful (struggle meter) and which evidence counts.
- `list_ids()` (optional): every bank id, for tests.

## N3: checks and learner model

- `lab.tasks.checks.run(bank_id) -> [check.result data]` (`{check, trap, passed, detail,
  rows?, bruinRun?}`), or tell me the function name you prefer.
- `lab.learner.update(learner, trap, correct) -> {trap, from, to, attempts}`,
  `lab.learner.mastery(learner) -> {traps: [{trap, score, attempts}]}`,
  `lab.learner.pick_next(learner, seen, tier) -> {skill, tier, reason, fallback, bandit?}`.

## P3 / P2: contract additions (optional, nothing breaks)

- `GET /api/session/:id/tables`, `.../rows` and `.../profile` take an optional
  `?task=t1` so a replay can show the workspace of any task of a finished session.
  Without it they use the current task (or the last one when the session is over).
- `GET /api/agents` items also carry `title` ("Lab head", "Examiner", ...).
- Portraits, when N2 has made them, are served at `/api/portraits/<file>`.
- `POST /api/session/start` accepts `{"mock": true}` to get a mock replay session from a
  live server; session ids starting `mock-` are mock replays.

- **Whispers are sealed by the server.** Before a task's `panel.transcript`,
  `panel.whisper` events have no `data.text` and carry `data.sealed: true` (api.md forbids
  whisper text before the verdict). Right after the `verdict`, a `panel.transcript` event
  (agent `ines`) carries `data.whispers: [{seq, agent, to, text}]`; from then on, and in
  any replay read from `since=0`, whispers arrive with their text, so hide it in a replay
  until the verdict has played. Mock mode does the same, and `contract/mock_session.jsonl`
  itself has sealed whispers plus the transcript.
- **task.picked** also carries `dictionary` (public Markdown, as in `GET /task`).
- **Checks.** Each task sends one `check.result` per check (five in the mock and the stub
  task: 4 pass, 1 fail). The Bruin run is one `sponsor.call` with `count: 1`; read
  `bruin.checksRun`/`checksFailed` from `GET /sponsors` (counted from `check.result`).
- **Glasser.** Live sessions read N2's cached Glasser retail numbers at the start (one
  `sponsor.call`), and Vale gets them as context for the brief. The mock has two calls.
- **Monitor.** Each live session starts with a `monitor.hit` (Telem's case of the day)
  when Telem answers.

## P3: answers to requests/p3.md

- **Who is who.** Events use the agent ids `vale`, `ines`, `sam`, `telem`, `riley`,
  `learner`, `system` (contract/events.md). `GET /api/agents` gives each agent's floor
  role: vale `director`, ines `referee`, sam `head`, telem `library`, riley `team-b`; the
  learner (`learner`) is `team-a`. Please key the floor on the agent id, not on
  summit-lab ids such as `head-team-a`.
- **agent.move.** The backend sends `data.place` from the contract list: `door`,
  `vale_office`, `learner_desk`, `riley_desk`, `shelves`, `terminal`, `panel_table`,
  `whiteboard`; `data.from` is where they leave from. The event's `to` is set when the
  walk is toward someone (for example Vale to `learner` for the brief); it is an agent id,
  not a place. Suggested mapping on your side: `vale_office` office, `learner_desk` the
  learner's desk, `riley_desk` Riley's desk, `shelves` library, `terminal` Telem's
  terminal, `panel_table` table, `whiteboard` Sam's desk, `door` lobby. The mock session
  walks to each of these places but `door` (people start there).
- **Rotation state.** `POST /api/session/start` returns every slot in `tasks` (titles of
  later slots are "Task 2", "Task 3" until picked); each pick sends `task.picked` with
  `taskId`, `title`, `brief`, `seconds`, `tier`, `claim`. Each grade sends
  `verdict` with `data.taskId` and `data.result` (`passed`/`failed`). The clock for a
  task starts at the `agent.move` of `riley` to `riley_desk` after the brief (the server's
  timer starts there too); `task.picked`'s `t` is close enough if you prefer.
- **Walks between tasks.** After each `task.end`, Vale goes back to `vale_office`, Sam to
  `whiteboard`, and Riley walks to `learner_desk` to see who won (then back to
  `riley_desk` when the next task opens). `from` is always where the agent really is, and
  a walk to the place an agent already stands is not sent.
