## N3: load `data/bench/results.csv` as Bruin's `bench_results`

N4 writes `data/bench/results.csv` (git-ignored, under `data/`), one row per
(split, dimension, system), replaced in place on rerun. Columns:

| column | type | meaning |
|---|---|---|
| split | text | `dev-A`, `dev-B` or `test` (dev halves split by dialogue, seed 2025) |
| dimension | text | `Mistake_Identification`, `Mistake_Location`, `Providing_Guidance`, `Actionability` |
| system | text | e.g. `single-opus-start`, `panel-opus-tuned` |
| macro_f1 | float | 3-class macro-F1, percent, one decimal |
| n | int | labelled replies scored |
| record | float | best BEA 2025 test-set score for that dimension (71.8, 59.8, 58.3, 70.9) |

Please load it as `bench_results` (ingestr or a Python asset). A useful check:
`macro_f1` between 0 and 100 when present, and `split` in the three values above.
Rows with split `test` have `macro_f1` blank (NULL) until CodaBench scores the
upload; `n` there is the number of replies predicted (1,547). The record is a
test-set number; rows on dev splits are not directly comparable to it.
