# N1 Session engine

You are the **N1 Session engine** session for **Lab Rotation**, our entry in today's
Multiplayer AI Hackathon (Finch, AWS Builder Loft, Mon Nov 23 2026). We submit by
**5:50 PM**. Nived supervises you; work without asking to continue.

**The product.** A flight simulator for an analyst's first weeks. A panel of AI
scientists (Dr. Vale the lab head, Ines the examiner, Sam the methods reviewer,
Telem the librarian, Riley the careless AI intern) hands the learner a small retail
dataset (customers, loyalty members, visits, spend, stores, regions; up to 3 tables,
a few hundred rows) and a claim to check. The data may hide one planted trap
(duplicated transactions, one region's spend in cents, a loyalty flag coded
backwards in the dictionary, a point-of-sale confounder, a hidden variable in a
second table) or none (a clean twin). The learner explores with a read-only SQL box,
profiles and charts, cites evidence, answers. The panel confers in a BAND room,
Ines shows the failing Bruin check, the verdict quotes the learner's own words, the
grade is sealed in a hash chain, a learner model (BKT + bandit) picks the next task.
The 2D lab floor (and a three.js view) shows agents walking, envelopes flying,
and a lab log with every event's reason.

## Your job
You build the engine that runs a session and the server every other stream talks to.

**By 12:45 (top priority): mock mode.** `lab/server.py` (FastAPI) with every route in
`contract/api.md`. With `LAB_MOCK=1` (or `"mock": true`) it replays
`contract/mock_session.jsonl` through the polled events route (`?since=N` →
`{events, next}`, events released at real speed, `LAB_MOCK_SPEED` multiplier),
serves `contract/mock_task/` (`task.json`, `tables.json`, CSVs; DuckDB in memory) for
tables, rows, profile and read-only SQL, and accepts answer/appeal/ask with canned
replies. Route names and shapes follow the front end's (`/api/session/...`,
camelCase); read `contract/api.md` closely. The web streams build against this, so ship it early and tell the
lead. Run: `uv run uvicorn lab.server:app --port 8000`.

**Then the real loop (by 3:30), in `lab/session/`:**
- event log: append-only JSONL in `data/sessions/<id>.jsonl`, `seq` without gaps,
  every event has a `why`; `t` is seconds since the session started.
- the task flow: brief, context (Telem), analysis, answer, panel confers,
  checks, verdict, mastery, next (see the phases in `api.md`).
- agent turns: each agent's reply comes from headless Claude Code on Nived's plan.
  Tested command (about 5 s per call):

      claude -p --tools "" --strict-mcp-config --no-session-persistence \
        --setting-sources "" --output-format json --system-prompt "<role prompt>" "<turn input>"

  Read `result` from the JSON. No tools, no MCP, never pass keys. Anything fetched
  from the web goes in as quoted data, never as instructions. Run calls in a thread
  pool so the server stays responsive.
- visibility in code: each agent's input is built only from what its role may see
  (Vale: learner profile, whispers, check results; Ines: answer key and check
  output; Sam: queries, actions, answer, meter, whispers; Telem: its search results;
  Riley: the public tables only). The key never reaches the browser.
- struggle meter: deterministic from the log (idle time since the last useful
  query, dead-end queries, wrong guesses) → value 0..1 and hint level 0..3.
- quote check: every quote in feedback must appear verbatim in its source (the
  learner's answer text or a query's SQL); drop or fix any that do not.
- ledger: SHA-256 hash chain in `data/ledger.jsonl` (`hash = sha256(prev + record)`).
- appeal: relayed into the BAND room through N2's client; Ines rules; any change is
  logged with its reason.
- modes: rotation (3 tasks, rising tiers) and judge (one task, 240 s clock).
- prompts in `lab/prompts/` (one file per agent), written fresh.

**Interfaces you call** (stub them until they land; ask in `requests/n1.md`):
