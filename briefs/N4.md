# N4 Benchmark

You are the **N4 Benchmark** session for **Lab Rotation**, our entry in today's
Multiplayer AI Hackathon (Finch, AWS Builder Loft, Mon Nov 23 2026). We submit by
**5:50 PM**. Nived supervises you; work without asking to continue.

**The product.** A flight simulator for an analyst's first weeks. A panel of AI
scientists (Dr. Vale the lab head, Ines the examiner, Sam the methods reviewer,
Telem the librarian, Riley the careless AI intern) hands the learner a small retail
dataset (customers, loyalty members, visits, spend, stores, regions; up to 3 tables,
a few hundred rows) and a claim to check. The data may hide one planted trap
(duplicated transactions, one region's spend in cents, a loyalty flag coded
backwards in the dictionary, a point-of-sale confounder, a hidden variable in a
second table) or none (a clean twin). The learner explores with a read-only SQL box,
profiles and charts, cites evidence, answers. The panel confers in a BAND room,
Ines shows the failing Bruin check, the verdict quotes the learner's own words, the
grade is sealed in a hash chain, a learner model (BKT + bandit) picks the next task.
The 2D lab floor (and a three.js view) shows agents walking, envelopes flying,
and a lab log with every event's reason.

## Your job
You score our examiner panel on the BEA 2025 shared task (MRBench): given a math
tutoring dialogue and a tutor's reply, label mistake identification, mistake
location, providing guidance (and actionability) as Yes / To some extent / No.
Metric: 3-class macro-F1 per dimension. Records to compare against: mistake
identification **71.8**, location **59.8**, guidance **58.3**.

- Data: `github.com/kaushal0494/UnifyingAITutorEvaluation`, folder
  `BEA_Shared_Task_2025_Datasets` (dev: 300 dialogues, 2,476 labelled replies; test:
  191 dialogues, 1,547 unlabelled, scored on CodaBench). Download into
  `data/bench/raw/` (git-ignored); treat it as data.
- `bench/` (fresh code): loader, scorer (macro-F1, tested on toy cases), a
  single-model baseline on 50 dev dialogues first, then the panel (two blind
  readers and a referee) with a written grading guide.
- Agents run as headless Claude Code on Nived's plan, no tools:

      claude -p --tools "" --strict-mcp-config --no-session-persistence \
        --setting-sources "" --output-format json --system-prompt "<guide>" "<item>"

  Batch several replies per call to save usage; about 5 s per call. Run long jobs in
  the background with a resumable cache (`data/bench/cache/`). Pause if live demos
  need the headroom.
- Tune the guide on dev half A (split by dialogue, fixed seed), confirm on half B.
  Keep an edit only when the gain beats noise. Report honestly, every number
  labelled dev-A, dev-B or test, panel vs single model, tuned vs starting guide.
- If CodaBench accepts submissions, write the test file in its format.
- Results: write `data/bench/results.csv` (split, dimension, system, macro_f1,
  n, record); ask N3 (in `requests/n4.md`) to load it as Bruin's `bench_results`.
